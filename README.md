# 教室故障与临时改排工作台（浏览器端）

面向校园后勤的**纯浏览器端**教室故障报修、事故封闭、工单维修与课程临时改排工作台。
技术栈：**React 18 + TypeScript + Vite + IndexedDB + WebWorker + Vitest**，无后端、无外部依赖，
所有数据保存在浏览器本地 IndexedDB，所有状态变更以**只追加事件流**记录，可随时回放。

## 1. 架构与职责

```
src/
├─ types.ts                 领域模型与事件定义（事件溯源）
├─ db/idb.ts                手写 IndexedDB Promise 封装（events/blobs/drafts/kv）
├─ engine/
│  ├─ reducer.ts            纯函数事件回放：事件流 -> 当前快照
│  ├─ scheduling.ts         排课引擎：候选过滤、方案一/方案二、重叠硬校验
│  ├─ commands.ts           命令层：操作 -> 事件（合并、门控、通知版本、草稿冲突）
│  ├─ scenario.test.ts      业务规则测试（15 个）
│  └─ idb.test.ts           IndexedDB 持久化/回放测试（2 个）
├─ worker/
│  ├─ incident.worker.ts    WebWorker：事件唯一写入口、回放快照、排课计算
│  └─ client.ts             Worker Promise 客户端
├─ state/store.tsx          React Context：快照、角色、在线开关、模拟时钟、草稿
├─ views/                   教师/设施/调度/维修/资源/事件回放 六个工作台
└─ lib/seed.ts              种子数据：5 间教室、A/B/S/P 四门课、距离矩阵
```

关键设计：

- **事件溯源 + 可回放**：业务状态（事故、封闭、工单、方案、通知）全部由事件回放得到，
  IndexedDB `events` 表只追加；“事件回放”页提供 seq 滑块，可查看任意历史时刻快照。
- **WebWorker 承担计算与持久化**：回放、DFS 换房搜索、候选教室评估都在 worker 线程，
  主线程只发消息、渲染 UI。
- **照片存 IndexedDB Blob**：不上传任何服务器，通过 ObjectURL 预览。

## 2. 本地启动

### 方式 A：Docker Compose（一键启动，推荐）

```bash
docker compose up -d --build
# 打开 http://localhost:8080
docker compose logs -f          # 查看日志
docker compose down             # 停止
```

多阶段构建：Node 22 编译静态资源 → Nginx 1.27 托管（含 SPA 路由回退与静态资源缓存）。

### 方式 B：本地开发（Node 22）

```bash
npm ci                 # 或 npm install
npm run dev            # 开发服务器，默认 http://localhost:5173
npm run build          # 类型检查 + 生产构建到 dist/
npm run preview        # 本地预览生产构建
```

### 测试

```bash
npm test               # vitest run，共 17 个用例
```

> 本隔离容器内未安装 Docker 守护进程，Dockerfile/compose 已按标准多阶段构建编写，
> 实际镜像构建与容器启动需在装有 Docker 的环境执行；容器内已实际执行的是
> `npm test`、`npm run build` 与 `vite preview` HTTP 冒烟验证（见第 6 节）。

  B 班 10:15-11:15 / 18 人 / 需实验台 / 原 B202；
  S 弹性研讨 10:15-11:15 / 12 人 / 需实验台 / 原 D301；
  P 班 14:00-15:00 / 原 B201（用于验证午后恢复）。
- 距离矩阵（分钟）含题目给定值：C101↔B201=8、C102↔B202=18、D301↔B202=7、C102↔D301=7。

## 5. 本题场景验证步骤（手工操作脚本）

> 任何时候可在“事件回放”页点“重置演示数据”回到初始状态。

### 步骤 1：模拟报修与重复合并

1. 身份切到**林老师**，模拟时钟设 09:40，扫 `B-B201`，选“漏水”，可加照片，提交。
2. 身份切到**周老师**，09:45 扫 `B-B202`，同样选“漏水”，提交。
3. 切到**设施工作台**：两条报修合并为**同一项事故**（第二条标“重复报修·已合并”），
   事故边界自动包含 B201、B202。

### 步骤 2：核准边界、封闭与工单

4. 设施人员把预计修复时间设为 12:00，点“核准边界并封闭房间”——B201/B202
   在 10:00-12:00 封闭（资源页可见红色封闭状态）。
5. 点“生成维修工单”，再切**维修工作台**可见工单；未核准边界时开工单会被拒绝。

### 步骤 3：核对两种改排方案（调度工作台）

候选核查表逐间列出距离、容量、设备、无障碍、安全、全时段空闲与不合格原因
（D301 对 A 班显示“无无障碍通道”，对 B 班显示“课程全时段不空闲”）。

- **方案一（仅移动受影响课程）**：A→C101、B→C102。
  学生分钟 = 24×8 + 18×18 = **516**，通知 2 个班。
- **方案二（弹性换房）**：A→C101、B→D301、S→C102。
  学生分钟 = 24×8 + 18×7 + 12×7 = **402**，比方案一**少 114**，
  但多移动 1 个班、多通知原本未受影响的 S 班。页面同时展示两组数字与通知对象差异。

### 步骤 4：教师确认后才发布

6. 调度员“采用”任一方案 → 方案进入“待教师确认”。
7. 分别切换到方案内每位教师，在教师工作台点“确认改排”；未全部确认时发布按钮禁用并显示进度。
8. 全部确认后调度员发布：每位师生收到**同一版本 v1 通知**（地点、时间一致）；
   课表页显示实际房间，任何同房同时段的重叠移动都会被引擎拒绝（测试覆盖）。

### 步骤 5：复测失败不自动回滚，14:00 复测通过才解封

9. 维修人员标记“已修复”——封闭状态**不变**（必须设施复测）。
10. 时钟设 11:30，设施人员点“复测失败”并记录原因：B201/B202 维持封闭，
    已发布的改排安排**不会按预计修复时间 12:00 自动回滚**（通知与课表均保持）。
11. 时钟设 14:00，点“复测通过并解除封闭”：两间房恢复可用（P 班午后课不受影响），
    但已发布安排仍保留——解封不等于回滚。

### 步骤 6：离线草稿、过期与冲突

12. 顶栏切“离线”：教师仍可查看已下载的带版本通知、保存报修草稿；提交按钮禁用。
13. 草稿 A：时钟拨到课程结束后再联网提交 → 判为**过期**，不能发布。
14. 草稿 B：离线保存草稿后，让该课程被改排发布，再联网提交 → 判为**冲突**，
    旧草稿进入冲突处理，不能覆盖新安排（草稿状态与原因显示在草稿表中）。

## 6. 已执行的自动化验证（实际结果）

在本容器 Node 22.14 下实际执行并通过：

- `npm test`（vitest）：**17/17 通过**，覆盖
  - 重复报修合并为一项事故、不同故障类型不合并；
  - 未核准不能开工单；核准后 B201/B202 同时封闭；
  - 候选过滤：无障碍否决 D301（A 班）、占用否决 D301（B 班）、封闭房不可选；
  - 方案一 = **516**、方案二 = **402（少 114）**，移动/通知对象与题目一致；
  - 人为同房同时段移动被拒绝（不得课程重叠）；
  - 教师未全部确认不能发布；通知 v1/v2 版本递增、旧版自动作废；
  - 11:30 复测失败维持封闭且已发布安排不回滚，14:00 复测通过才解封；
  - 离线草稿的过期判定与改排冲突判定；
  - IndexedDB 事件持久化后“刷新重建”回放一致、草稿与 Blob 存取、重置清空。
- `npm run build`：TypeScript 严格类型检查通过，Vite 产出主包与独立 worker chunk。
- `vite preview` 冒烟：`/`、主 JS、worker JS 均返回 200。

浏览器内的点击级交互未接入自动化浏览器测试，按第 5 节脚本手工核对；
引擎规则均有对应自动化用例，UI 与 worker 共用同一份纯函数引擎。

## 7. 数据与隐私

全部数据（事件、草稿、照片）仅存在当前浏览器的 IndexedDB（库名
`incident-workbench-db`），不发起任何网络请求；清空浏览器站点数据或使用页内
“重置演示数据”即可恢复初始状态。
